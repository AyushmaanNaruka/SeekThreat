# evals/

The evaluation harness. **Built in September, not January.**

We cannot retrofit measurement onto a finished system. Bad numbers in month two are fine.
Missing numbers in month six are fatal.

**Co-owned by all three of us.** Anything owned by one person becomes nobody's priority.

## Two tracks

**Track A — the brief's metrics, satisfied literally**

| Metric | Applied to |
|---|---|
| Accuracy, precision, recall, F1 | Vulnerability detection vs `lab/ground_truth.yaml` |
| Macro-F1 | CVE -> ATT&CK classifier |
| MAE | Derived CVSS for unenriched CVEs |
| BLEU / ROUGE | Assistant answers |

**Track B — what actually measures the system**

| Metric | Target |
|---|---|
| Faithfulness | >= 0.85 |
| Context precision | >= 0.80 |
| Context recall | >= 0.80 |
| Answer relevancy | >= 0.85 |
| Citation accuracy | >= 0.95 |
| Attack path validity | >= 0.90 (manual, N=50) |
| Enrichment coverage vs NVD-only | **Measured once on real mirrors (2026-10-11), with caveats.** Per field, multi-source vs NVD-only: CVSS 100.0% vs 100.0%, CWE 92.0% vs 92.0%, description 100.0% vs 100.0%, EPSS 100.0% vs 0.0%. Excluding EPSS (which the baseline does not load by design) the gain is **+0.0 pp**; the four-field 98.0% vs 73.0% (+25.0 pp) is entirely EPSS. 50 hand-picked CVEs, batch-attested labels. See [`results/enrichment_coverage_real.md`](./results/enrichment_coverage_real.md) and its reviewer notes. |
| Dedup precision/recall | vs DefectDojo on identical input |

Report both. Explain why Track B matters more. Questioning the metric is itself a
differentiator.

## Golden dataset — target ~500 items

| Count | Type |
|---|---|
| 150 | Factual CVE lookups with verifiable ground truth |
| 100 | Remediation questions with authoritative references |
| 75 | Attack path questions against known lab topologies |
| 75 | Prioritization — "what should I fix first and why" |
| 50 | Adversarial / out-of-scope, where the right answer is "I don't have that data" |
| 50 | Multi-hop requiring graph traversal plus retrieval |

Lives in `evals/golden/`.

## Rule

**All reported evaluation numbers must come directly from executed code against real mirrors.** Never generate placeholder metrics or estimates. Synthetic-fixture runs are harness checks and carry a SYNTHETIC banner.

Measured so far: enrichment coverage, once, on real mirrors dated 2026-10-11
(`results/enrichment_coverage_real.*`). ERS ranking corroboration was run once on the same
mirrors with the pre-review harness (`results/ers_validation_results.*`). It is smoke-level only
and must be regenerated with the revised harness.

## Reproducing the real-mirror runs

The mirrors live in `data/enrichment_cache/`, which is **gitignored** (`.gitignore`: `data/`).
Upstream feeds change daily, so a later sync gives different files. The committed results record
each mirror's sha256, mtime and `synced_at`. These identify the snapshot, but **the snapshot
itself is not archived anywhere**, so the 2026-10-11 numbers cannot be regenerated byte-for-byte.
A rerun measures a new snapshot and must be committed as a new, dated result.

```bash
# 1. Sync mirrors (network allowed only here). The full mirrors (KEV, EPSS, ExploitDB,
#    Metasploit) need no input; the per-CVE sources (CVE.org, Vulnrichment, NVD, EUVD) fetch
#    only the IDs in the CVE file.
python -m services.enrichment.sync_feeds --source all   --cve-file evals/golden/eval_cve_list.txt --cache-dir data/enrichment_cache

# 2. Enrichment coverage (offline). Defaults write synthetic-fixture results; pass the real
#    output paths explicitly.
python evals/enrichment_coverage.py --dataset evals/golden/enrichment_baseline.json   --cache-dir data/enrichment_cache   --output-json evals/results/enrichment_coverage_real.json   --output-md evals/results/enrichment_coverage_real.md

# 3. ERS ranking corroboration (offline). Refuses to write real results unless both output
#    paths are given; a missing --cache-dir is an error.
python evals/ers_validation.py --dataset evals/golden/enrichment_baseline.json   --cache-dir data/enrichment_cache   --output-json evals/results/ers_validation_results.json   --output-md evals/results/ers_validation_results.md
```

Without arguments, both eval scripts run on the synthetic fixtures in `tests/fixtures/enrichment/`
and write `results/enrichment_coverage_results.*` and `results/ers_validation_synthetic.*`.
Because the per-CVE sources were fetched for exactly the evaluated IDs, their coverage partly
measures fetch success.
